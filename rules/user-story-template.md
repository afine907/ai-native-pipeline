# 用户故事模板

本文档定义用户故事的编写规范和标准模板，确保生成的用户故事清晰、可操作。

---

## 1. 用户故事模板

### 1.1 标准格式

```
作为 [角色]，我希望 [功能]，以便 [收益]
```

**示例**：
```
作为 注册用户，我希望 通过手机号登录，以便 快速进入应用
```

### 1.2 扩展格式

```
作为 [角色]，
我希望 [功能/行为]，
以便 [收益/价值]

## 验收条件
- [ ] 条件1
- [ ] 条件2

## 优先级
P0（必须实现）
```

---

## 2. 用户故事组件

### 2.1 角色定义

| 角色类型 | 说明 | 示例 |
|----------|------|------|
| 内部用户 | 公司员工、系统管理员 | 运营人员、管理员 |
| 外部用户 | 客户、合作伙伴 | 普通用户、商家 |

### 2.2 功能描述

- 使用**动词**开头（登录、查看、创建、删除）
- 描述用户期望的系统行为
- 保持简洁，不超过一句话

### 2.3 收益描述

- 说明功能带来的实际价值
- 从用户角度出发
- 避免技术实现细节

## 3. 验收条件模板

### 3.1 Gherkin格式（推荐）

```gherkin
功能: [功能标题]
  场景: [场景描述]
    假设 [前置条件]
    当 [操作]
    那么 [预期结果]
```

**示例**：
```gherkin
功能: 用户登录
  场景: 使用正确账号密码登录
    假设 用户已注册
    当 用户输入正确的用户名和密码
    那么 用户成功登录并跳转到首页

  场景: 使用错误密码登录
    假设 用户已注册
    当 用户输入错误的密码
    那么 显示错误提示"用户名或密码错误"
```

### 3.2 检查清单格式

```markdown
## 验收条件

### 正常场景
- [ ] 用户能使用用户名密码登录
- [ ] 登录成功后跳转到首页
- [ ] 登录成功后返回用户信息

### 异常场景
- [ ] 用户名不存在，提示"用户不存在"
- [ ] 密码错误，提示"用户名或密码错误"
- [ ] 账号被禁用，提示"账号已被禁用"
- [ ] 输入为空，提示"请输入用户名和密码"

### 边界场景
- [ ] 密码前后空格自动去除
- [ ] 用户名大小写不敏感
- [ ] 登录会话过期后自动跳转登录页
```

## 4. 优先级定义

### 4.1 优先级等级

| 优先级 | 含义 | 开发安排 |
|--------|------|----------|
| P0 | 核心功能，必须实现 | 第一阶段 |
| P1 | 重要功能，计划内实现 | 第二阶段 |
| P2 | 增强功能，择机实现 | 第三阶段 |
| P3 | 优化功能，后续迭代 | 后续版本 |

### 4.2 优先级判断标准

**P0（核心功能）**：
- 没有此功能，系统无法正常使用
- 业务流程的核心步骤
- 法规合规要求的必选项

**P1（重要功能）**：
- 对用户体验有较大影响
- 大多数用户会使用的功能
- 竞品都已具备的功能

**P2（增强功能）**：
- 提升用户体验但非必需
- 部分用户会使用的功能
- 可后续迭代

**P3（优化功能）**：
- 锦上添花的功能
- 体验优化类
- 可长期规划

## 5. 用户故事示例

### 示例：电商下单

```markdown
## 用户故事

### US001 - 浏览商品列表
作为 购物用户，
我希望 查看商品列表，
以便 了解有哪些商品可供购买

验收条件：
- [ ] 商品列表分页展示，每页20个
- [ ] 显示商品名称、价格、图片
- [ ] 支持按价格、销量排序
- [ ] 支持筛选分类、品牌

优先级：P0

---

### US002 - 加入购物车
作为 购物用户，
我希望 把商品加入购物车，
以便 统一结算

验收条件：
- [ ] 点击加入购物车成功
- [ ] 购物车数量角标更新
- [ ] 购物车页面显示商品信息
- [ ] 支持修改数量、删除商品

优先级：P0

---

### US003 - 微信支付
作为 购物用户，
我希望 使用微信支付订单，
以便 完成购买

验收条件：
- [ ] 订单页面显示微信支付选项
- [ ] 点击唤起微信支付
- [ ] 支付成功更新订单状态
- [ ] 支付失败显示错误提示

优先级：P0
```

## 6. 用户故事检查清单

生成用户故事时，必须检查以下项目：

- [ ] 角色定义清晰（是谁）
- [ ] 功能描述具体（要什么）
- [ ] 收益说明价值（为什么）
- [ ] 验收条件可测试
- [ ] 优先级定义合理
- [ ] 与其他用户故事的依赖关系已标注
- [ ] 边界条件和异常场景已考虑
